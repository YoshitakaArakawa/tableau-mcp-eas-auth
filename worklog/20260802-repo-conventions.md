# リポ規約の導入(worklog/ と verification/)

日付: 20260802

## 背景

このフォークは AI(Claude Code)との協業で開発しており、PR 本文級の情報(背景・設計判断・
検証)が GitHub のデータベースにしか残らないと、クローンやローカルの AI セッションから
見えない。作業の知見をリポ内に正本として残す仕組みが必要だった。

## 変更内容

- `worklog/` — PR 単位の作業記録。正本はリポ側で、PR 本文はその要約 + リンク
- `verification/` — 機能ごとの手動検証記録。モック依拠の自動テストでは検証できない
  「モックが本物と同じ挙動をする」という仮定を、実機で潰した証跡を置く
- `CLAUDE.md` 末尾に「Fork Conventions」節を追加(AI セッションが規約に自動的に従うため)

## 設計判断

- **PR 単位を採用、コミット単位は不採用**: コミットにはメッセージが既にあり、
  コミット単位のファイルは数が爆発して読まれなくなる
- **時系列ワークログではなく変更スコープの記録**: 日次ログは腐りやすい。ADR に近い
  「その変更で何を判断したか」の形は腐りにくい
- **CLAUDE.md は全面新規化せず末尾追記**: CLAUDE.md は upstream 由来で、このフォークは
  upstream main を定期 merge する。全面書き換えは以後の merge で毎回 conflict するため、
  本文温存 + 末尾のフォーク専用節とした
- **検証ハーネスはコミットしない**: 再検証したい人は自分で作れる前提(ほぼ自分用の
  フォーク)。記録に再現手順の要点だけ残す

## 検証

ドキュメントのみの変更。リンク切れがないことを目視確認。

## 残課題

なし。
