# worklog/

PR 単位の作業記録(背景・設計判断・検証)を置くフォルダ。**正本はここで、PR 本文は
このファイルの要約 + リンク**とする。GitHub の PR 本文はクローンや作業ツリーから
見えないため、AI や将来の自分が読む情報はリポ内に残す。

## 規約

- **作る条件**: 背景・設計判断・検証を伴う PR には 1 枚書く。typo 修正級の軽微な PR は不要
- **タイミング**: PR を開く**前**にブランチ内で書く(PR 本文はその要約として書く)
- **命名**: `YYYYMMDD-<slug>.md`(日付は worklog 作成日)
- **構成**: 背景 / 変更内容 / 設計判断(採用だけでなく**不採用案と理由**も)/
  検証([verification/](../verification/README.md) へのリンク)/ 残課題
- **分担**: 事実の証跡は `verification/`、経緯と判断は `worklog/`。相互リンクで結ぶ
- **機微情報禁止**: 個人メールアドレス・マシンパス・実サイト名・LUID・トークン・
  個人デプロイの URL は書かない(抽象表現かプレースホルダにする)
